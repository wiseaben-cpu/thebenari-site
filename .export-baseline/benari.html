01The system

What Benari is

Benari is a personal and executive assistant that runs as a WhatsApp thread. I text it the way I'd text a chief of staff — what does my day look like, what actually needs me, remember this about that person — and it answers from my calendar, my inbox, my task list, and its own memory.

It is a prototype, not a product. One person can use it: me. The conversation above is scripted with invented names to show the shape of a real exchange. The system underneath it is real, and it runs continuously.

02Architecture

How Benari works

Every message takes the same path. The sender is checked against a list of who is allowed to talk to it. Context is rebuilt from the database — the recent thread, known facts, whatever a search of memory turns up. One Claude call then runs with the tools for the relevant domain attached. The whole turn is written back to the database before the reply goes out.

The brain keeps nothing

Claude holds no state between calls. Every turn starts empty and is reassembled from Postgres, which is the only source of truth. The model does the reasoning. It is never the record.

A skill is a row, not a rewrite

The orchestrator has no idea what a calendar is. At runtime it reads a registry table to find which sub-agent handles the request and which tools to hand the model. A domain is that registry row plus a small MCP server that does the actual work, so adding one changes no routing code.

Memory is one database

Postgres with pgvector holds relational rows, structured facts, and embeddings in one place. Recall blends vector similarity, keyword match, and confidence, and decays older entries so stale context ranks lower. A background job retires memories that get contradicted, and brings one back if I say it again.

03Today

What Benari can do today

Four domains are live. Each is its own tool server behind the same interface.

Calendar

Reads the calendar, lists what's coming, and finds free time. Creating, moving, or deleting an event is drafted first.

Email

Searches and reads threads, separates what needs a reply from what is FYI, and writes the draft. Sending waits.

Tasks

Adds, lists, and closes tasks in the same thread as everything else, so a second app never has to be opened.

Notes

Reads a folder of markdown notes and pulls the relevant passage into an answer, naming the file it came from.

Nothing outward happens without a yes

Any tool that sends, deletes, or changes something outside the system is flagged in the registry. The orchestrator stops it, shows the draft, and waits for a literal YES before it runs. That gate is code, not an instruction in the prompt, so the model cannot talk its way past it. Anything that comes back from an email or a note is wrapped and treated as data, never as instructions.

What it can't do yet

A second switch sits in front of that gate. While it is on, any tool that writes to an outside account is refused before it can even be drafted — so for now Benari reads my accounts and drafts the reply, and I send it. It also only speaks when spoken to: the delivery path for unprompted messages exists, the morning briefing that would use it does not. Voice is built and not yet in use.
